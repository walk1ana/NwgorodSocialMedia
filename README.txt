NEWGOROD — RELEASE CANDIDATE
============================

В ЭТОМ ПАКЕТЕ
- Удалены предзаполненные демонстрационные публикации и профили.
- Удалены пользовательские подписи «демо» и «демо-данные».
- Для новой установки лента и истории начинаются пустыми.
- Обновлён ключ локального хранилища и версия PWA-кэша.

ВАЖНО: ЭТО ЕЩЁ НЕ ПОЛНОЦЕННАЯ ОБЩАЯ СОЦИАЛЬНАЯ СЕТЬ
Текущий проект — клиентское PWA-приложение. Supabase Auth используется для
регистрации и входа, но публикации, лайки, комментарии, подписки, истории и
избранное пока сохраняются в localStorage браузера. Они не синхронизируются
между устройствами и аккаунтами. Поиск пользователей, доставка сообщений,
жалобы и модерация также не реализованы как серверные функции.

Шифрование в разделе «Сообщения» защищает локальные заметки на этом устройстве.
Оно не обеспечивает доставку сообщений другому пользователю и не является
полноценным сквозным шифрованием (E2E) между собеседниками.

ЧТО НУЖНО ДЛЯ ПОЛНОГО ПУБЛИЧНОГО РЕЛИЗА
1. Создать серверные таблицы пользователей/профилей, публикаций, комментариев,
   реакций, подписок, историй и диалогов.
2. Настроить Row Level Security (RLS) для каждой таблицы и проверить политики
   доступа для чтения, создания, изменения и удаления.
3. Реализовать загрузку изображений в Storage с ограничениями размера и типа.
4. Реализовать серверную доставку сообщений и отдельный проверенный протокол
   E2E-шифрования, если нужна приватная переписка.
5. Добавить жалобы, блокировки, модерацию, антиспам и правила сообщества.
6. Настроить восстановление аккаунта, подтверждение почты, обработку ошибок,
   резервное копирование и мониторинг.
7. Провести тестирование безопасности и проверку на мобильных устройствах.

ПУБЛИКАЦИЯ PWA
1. Разместите содержимое папки проекта в корне HTTPS-хостинга
   (например, GitHub Pages).
2. В Supabase настройте Site URL и Redirect URLs для адреса сайта.
3. В auth.js используйте только публичный publishable/anon ключ.
   Никогда не добавляйте service_role или secret key в клиентский код.
4. Проверьте регистрацию, подтверждение почты, вход и выход на опубликованном
   домене. Убедитесь, что в Supabase настроены безопасные политики RLS.

Не публикуйте реальные персональные данные до завершения серверной настройки,
модерации и проверки безопасности.
