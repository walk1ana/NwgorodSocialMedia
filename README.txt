NEWGOROD — СТАРТОВЫЙ ПРОЕКТ
===========================

ЧТО ЭТО
Это первая демонстрационная версия NewGorod — адаптивное веб-приложение (PWA),
которое можно разместить на GitHub Pages и добавить на главный экран iPhone.

ВАЖНО ПРО ФУНКЦИИ
- Публикации, лайки, комментарии, подписки, профиль, истории и фото работают
  локально в браузере этого устройства.
- В разделе «Сообщения» добавлен локальный зашифрованный чат-черновик: AES-256-GCM, ключ выводится из парольной фразы через PBKDF2-SHA-256.
- Это НЕ общая социальная сеть: разные пользователи пока не видят данные друг друга.
- Не размещайте личные или чувствительные данные. Для реального запуска нужны
  серверная база данных, вход пользователей, правила доступа, защита от спама,
  жалобы/блокировки и модерация контента.
- Демо-данные сохраняются в localStorage браузера. Очистка данных браузера может
  удалить их. Фото ограничены 1,5 МБ на файл, но хранилище браузера ограничено.

КАК ОТКРЫТЬ НА WINDOWS
1. Скачайте ZIP и распакуйте папку NewGorod.
2. Откройте папку.
3. Дважды нажмите index.html — проект откроется в браузере.
   Для локальной проверки этого достаточно, но установка PWA и офлайн-кэш
   надёжнее работают после публикации по HTTPS на GitHub Pages.

КАК ЗАГРУЗИТЬ НА GITHUB PAGES
1. Войдите в GitHub и нажмите New repository.
2. Название: newgorod (можно другое). Для простоты выберите Public.
3. Создайте репозиторий.
4. Нажмите Add file → Upload files.
5. Откройте распакованную папку NewGorod и перетащите ВСЕ файлы из неё
   (index.html, styles.css, app.js, manifest.webmanifest, sw.js, icon.svg,
   README.txt) в окно загрузки GitHub. Не загружайте ZIP вместо файлов.
6. Нажмите Commit changes.
7. В репозитории откройте Settings → Pages.
8. В разделе Build and deployment выберите Deploy from a branch.
9. Branch: main; Folder: /(root). Нажмите Save.
10. Подождите минуту-две. GitHub покажет адрес вида:
    https://ВАШ-ЛОГИН.github.io/newgorod/

КАК ДОБАВИТЬ НА IPHONE
1. Откройте полученный адрес в Safari на iPhone.
2. Нажмите кнопку «Поделиться».
3. Выберите «На экран Домой».
4. При желании включите «Открывать как веб-приложение».
5. Нажмите «Добавить».

ОБНОВЛЕНИЕ
После изменения файлов загрузите обновлённые файлы в репозиторий.
Если iPhone показывает старую версию, закройте приложение и обновите страницу
в Safari; иногда нужно немного подождать обновления кэша.

НАСТРОЙКА РЕГИСТРАЦИИ И ВХОДА (SUPABASE AUTH)
1. Открой https://supabase.com/ и создай проект.
2. В Supabase открой Project Settings → API (или Data API / API Keys).
3. Скопируй Project URL и anon/public key (не secret/service_role).
4. На компьютере открой auth.js через Блокнот.
5. Замени значения:
   SUPABASE_URL = "ВСТАВЬТЕ_SUPABASE_PROJECT_URL";
   SUPABASE_ANON_KEY = "ВСТАВЬТЕ_SUPABASE_ANON_KEY";
   на свои значения, сохрани файл.
6. В Supabase открой Authentication → URL Configuration.
   Добавь точный адрес GitHub Pages в Site URL и Redirect URLs,
   например https://ВАШ-ЛОГИН.github.io/newgorod/** .
7. В Authentication → Providers проверь, что Email включён.
8. Загрузи обновлённые index.html, app.js, auth.js и styles.css в GitHub.
9. Открой сайт. Создай аккаунт с почтой и паролем не короче 8 символов.
   Если включено подтверждение почты, перейди по ссылке из письма, затем войди.

БЕЗОПАСНОСТЬ
- Пароли обрабатывает Supabase Auth; сайт не сохраняет пароль в localStorage.
- В GitHub Pages допустимо использовать только anon/public key. Он не является
  административным секретом; доступ к данным защищается политиками RLS.
- НИКОГДА не вставляй service_role или secret key в auth.js.
- Добавление входа ещё не делает ленту общей: посты/комментарии пока хранятся
  локально в браузере каждого пользователя. Для общей соцсети далее создадим
  таблицы базы данных и включим Row Level Security.
- Не используй личную основную почту или пароль, который используешь где-то ещё,
  в тестовом проекте. Не делись кодами подтверждения и паролем.


ЛОКАЛЬНОЕ ШИФРОВАНИЕ СООБЩЕНИЙ
- Открой раздел «Сообщения» и задай отдельную парольную фразу длиной от 10 символов.
- Сообщения шифруются в браузере с помощью Web Crypto API (AES-256-GCM).
  Для каждого сообщения создаётся случайный 96-битный IV; ключ выводится через
  PBKDF2-SHA-256 с индивидуальной солью и 310 000 итераций.
- В localStorage сохраняются только соль, проверочный зашифрованный маркер и
  шифротекст с IV. Парольная фраза и ключ не сохраняются.
- Кнопка «Заблокировать» удаляет ключ из памяти вкладки. Для просмотра снова
  потребуется парольная фраза.
- Потерянную парольную фразу восстановить нельзя. Очистка переписки удаляет
  сохранённые шифротексты.
- Это локальная демонстрация, а не доставка личных сообщений между аккаунтами.
  Для полноценного E2E-чата нужны серверная доставка, проверенные открытые ключи
  собеседников, протокол обмена ключами и защита от подмены личности.
- Web Crypto работает на HTTPS или localhost. На GitHub Pages используется HTTPS.


Дополнительные функции (feature pack):
- Избранное: сохранение и отдельный список публикаций в профиле.
- Редактирование и удаление собственных публикаций.
- Сортировка ленты по новизне и популярности.
- Копирование текста публикации через кнопку «Поделиться».
- Фильтрация ленты по тематическим кнопкам в разделе «Исследовать».
- Загрузка фото профиля (до 500 КБ).

Все эти действия сохраняются локально в браузере отдельно для вошедшего аккаунта. Они не становятся общими между пользователями, пока не подключена база данных Supabase и соответствующие политики доступа (RLS).
