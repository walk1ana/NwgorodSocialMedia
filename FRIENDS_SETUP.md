# NewGorod — друзья и личные чаты

В приложении есть поиск жителей, заявки в друзья, список друзей и личные чаты с принятыми друзьями. Принятие заявки выполняется одной серверной операцией, а новые сообщения приходят через Supabase Realtime.

## Настройка Supabase

В текущей настройке проекта уже должна существовать таблица `public.profiles`. Запусти следующие миграции по порядку в Supabase Dashboard → SQL Editor:

1. `supabase/migrations/202611240002_friend_requests.sql`
2. `supabase/migrations/202611250001_friend_messages.sql`

Если это новый Supabase-проект, сначала восстанови базовую схему аккаунтов и профилей, затем запусти миграции выше. Для отправки и открытия чатов нужны включённые Supabase Auth и Realtime. Миграция чатов создаёт таблицы переписок и ограничивает чтение/отправку сообщений подтверждёнными друзьями через RLS.

## Опубликуй сайт

Загрузи файлы проекта в GitHub Pages, включая обновлённые `index.html`, `styles.css`, `supabase-integration.js`, `sw.js` и каталог `supabase/migrations`.

## Проверка

Лучше проверить двумя разными тестовыми аккаунтами:

1. В аккаунте A найди по имени аккаунт B и нажми «Добавить».
2. Войди в аккаунт B — заявка должна появиться во «Входящих заявках».
3. Нажми «Принять» и обнови список — оба аккаунта должны появиться друг у друга в «Моих друзьях».
4. Открой «Чаты», выбери друга и отправь сообщение; проверь, что оно появляется в обеих сессиях.
5. Проверь, что посторонний аккаунт не может открыть этот чат.

Поиск выполняется по `profiles.display_name`. Он ищет только зарегистрированные аккаунты, которые уже имеют профиль в Supabase.

## Безопасность

Доступ к заявкам и сообщениям ограничен RLS. Принимать/отклонять заявку может только получатель, а личный чат открывается серверной функцией только при существующей дружбе. Не добавляй `service_role` или пароль базы данных в клиентский код.
